Overview

Making complex data accessible to everyone

Insightful is a B2B SaaS analytics platform used by marketing teams at mid-market companies (200-2000 employees) to track campaign performance, customer engagement, and revenue attribution. The platform aggregates data from 15+ sources (Google Analytics, Meta Ads, Salesforce, HubSpot, etc.) into a unified dashboard.

The problem: the existing dashboard was built by engineers for engineers. It was powerful but impenetrable — dense tables, cryptic metric names, no contextual guidance, and a chart builder that required SQL knowledge. Non-technical marketing managers (the primary buyers) struggled to extract insights without requesting help from their analytics team.

I was tasked with redesigning the core dashboard experience to make it intuitively usable for non-technical users while preserving the depth that power users relied on.

Discovery

Understanding two very different users

Through interviews with 15 users and analysis of FullStory session recordings, I identified three distinct personas:

"I need to know if our campaigns are working — in plain English, not SQL."
🔬

"I need granular control over queries and the ability to build custom views."
👔
James, VP Marketing

"I need a 30-second overview before my Monday morning meeting."

The critical insight: each persona needed a fundamentally different level of abstraction. Sarah needed curated summaries; Alex needed raw data access; James needed a snapshot. The old dashboard tried to serve all three with the same dense interface and failed everyone.

Challenge 1

Progressive disclosure — one dashboard, three depths

Rather than building three separate views, I designed a progressive disclosure system where users naturally move from high-level to detailed as needed.

Layer 1: Executive Summary (James)

A fixed-height strip at the top of the dashboard showing 4-6 "headline metrics" — KPIs selected during onboarding with trend indicators (↑↓) and plain-language context ("Revenue is up 12% vs. last month"). One glance, 5 seconds, done.

Layer 2: Interactive Cards (Sarah)

Below the summary, a grid of draggable, resizable cards — each representing a data view (channel performance, funnel conversion, cohort retention, etc.). Cards show a chart and a natural-language insight sentence generated by the backend. Clicking a card expands it for more detail. No SQL required.

Layer 3: Data Explorer (Alex)

A slide-out panel accessible from any card via "Explore Data →" link. Offers full query builder with visual filters, custom date ranges, dimension breakdowns, and raw table export. Power users get their depth without cluttering the main dashboard.

Before

One dense view with 40+ metrics, 3 data tables, and a chart builder requiring SQL. Average time to answer "How did email perform last month?": 4m 22s. Task success rate: 43%.

After

Three progressive layers. Headline metrics → interactive cards → data explorer. Average time to answer "How did email perform last month?": 38 seconds. Task success rate: 91%.

Challenge 2

Making charts readable for non-technical users

The old dashboard used 8 different chart types with no contextual guidance. Line charts had unlabeled axes, bar charts used up to 12 colors with no legend hierarchy, and funnel charts used percentage labels that confused users ("Is 45% good or bad?").

Chart Design Principles

  • Limit to 4 chart types: Line (trends over time), Bar (comparisons), Donut (composition), Funnel (conversion stages). Removed scatter plots, heat maps, and stacked areas that confused non-technical users.
  • Semantic color palette: Green = good (above target), red = needs attention (below target), blue = neutral (informational). Consistent across all charts. Color-blind safe with pattern fills as fallback.
  • Inline annotations: Charts include contextual labels like "Best day: Tuesday" or "Below target by 8%" directly on the visualization, eliminating the need to mentally process raw numbers.
  • Hover storytelling: Tooltips show not just the data point value but a contextual sentence: "On March 15, email drove 234 signups — 42% above your 30-day average."

Usability Test Result: When asked "Which channel performed best last month?", task success rate improved from 38% (old charts) to 94% (new design). Average time dropped from 2m 10s to 18 seconds. The most impactful change? Adding the inline annotations — 13/15 participants cited them as "the most helpful thing."

Challenge 3

Onboarding & empty states

30% of new users churned within the first week, citing "I didn't know where to start" as the primary reason. The old dashboard showed an empty grid with a single "Create Widget" button — intimidating for a non-technical user.

Solution: Guided First Experience

  1. Data source wizard: A 3-step connection flow with pre-built integrations for the top 8 platforms (Google Analytics, Meta Ads, Shopify, Salesforce, HubSpot, Mailchimp, Stripe, Google Sheets). One-click OAuth authentication with progress indicator.
  2. Template dashboards: After connecting sources, users choose from 6 industry-specific templates (E-commerce, SaaS, Media, Agency, Non-profit, Custom). Templates come pre-populated with relevant metrics, charts, and natural-language insights.
  3. Interactive walkthrough: A 4-step tooltip tour highlighting: (1) headline metrics, (2) how to interact with cards, (3) how to customize layout, (4) how to access the data explorer. Dismissible, re-accessible from Help menu.

Result: First-week retention improved from 70% to 89% after implementing the onboarding flow. Users who completed the template selection step showed 3.2× higher 90-day retention than those who skipped it.

Design System

Dashboard-specific component library

I created a focused component library tailored for dashboard interfaces:

  • Metric Card: 4 variants (simple, with trend, with sparkline, with comparison). Supports 3 sizes (compact, default, expanded).
  • Chart Container: Standardized wrapper with title, date range selector, expand/collapse, and export actions. Responsive — charts reflow from 2-column to 1-column on smaller viewports.
  • Filter Bar: Persistent horizontal filter strip with date range picker, dimension filters, and saved filter presets. Supports keyboard navigation.
  • Data Table: Sortable, filterable table with sticky headers, column resizing, inline sparklines, and row-level actions. Pagination + "load more" hybrid pattern.
  • Side Panel: Slide-out panel (400px width) for detailed views, used by the Data Explorer and metric detail views. Supports nesting up to 2 levels.

All components follow an 8px grid, use the product's token system for theming (light/dark mode), and meet WCAG 2.1 AA accessibility standards.

Reflection

Lessons learned

  1. Progressive disclosure is the answer to "simple vs. powerful": You don't have to choose between novice and expert users. Layer the complexity, let users go deeper on demand, and default to the simpler view.
  2. Charts need words: Data visualization alone isn't enough for non-technical users. Adding natural-language annotations transformed charts from "things I have to interpret" to "things that tell me answers."
  3. Onboarding is product design: The first 5 minutes determine whether a user becomes a retained customer. Templates and guided setup aren't nice-to-haves — they're core product features.
